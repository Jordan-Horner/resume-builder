# Feedback Memory

Accepted user guidance lives under `editorial/rules/`. Each JSON rule preserves
one current interpretation and its accepted revision history. Rules are writing
guidance, never career evidence.

Normal conversational corrections begin as temporary sessions under
`build/feedback/`. Repeated feedback updates the same session, and only its
latest revision guides the next rewrite. Builds and post-cold compliance review
pin that open revision. After the user accepts the reviewed preview, reusable
guidance is promoted here without invalidating that preview when its effective
meaning is unchanged. Cosmetic or one-off corrections
close without creating a durable rule; factual corrections route through vault
hydration.

The builder resolves only rules relevant to a synthesis plan's facts, story,
resume, direction, and section. A prior sentence may be retained as an example,
but it is not mandatory wording unless the user explicitly requested that exact
language. The independent cold reviewer does not see feedback memory. A
separate post-cold compliance decision checks applicable accepted rules and
open revisions before preview or minting.
