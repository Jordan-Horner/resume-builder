## Design Context

### Users

The primary user is a job seeker reviewing evidence-grounded resumes inside the
Codex desktop app before approving a final PDF. Career professionals may review
the same web preview, while recruiters and hiring managers receive the minted
resume. The key job is to inspect content quickly, catch weak or unsupported
claims, and approve a trustworthy final artifact without navigating technical
build output.

### Brand Personality

Credible, calm, and professional. The interface should feel like a careful
editorial and career-review tool: confident without hype, polished without
decoration, and explicit about draft, review, and approval state.

### Aesthetic Direction

Use a refined editorial-resume aesthetic in light mode. Preserve an ATS-safe,
single-column paper document with restrained color, strong typography, and
clear hierarchy. The web preview should feel like a faithful review surface for
the printable resume rather than a dashboard or marketing page. Avoid generic
AI styling, decorative cards, visual noise, dark neon themes, and UI elements
that compete with the resume itself.

### Design Principles

1. Keep the resume—not the surrounding interface—as the visual focus.
2. Make review state and next action immediately understandable without adding
   clutter to printed output.
3. Preserve readable type, hierarchy, and spacing across the Codex review panel,
   ordinary desktop browsers, and print; never trade print integrity for a
   screen-only effect.
4. Favor restrained, accessible color and selectable text over decoration,
   icons, images, or complex layouts that weaken ATS compatibility.
5. Verify actual viewport measurements and rendered output before treating a
   scaled screenshot as a layout defect.
